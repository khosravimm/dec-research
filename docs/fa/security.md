# امنیت و کنترل انتشار عمومی

**مدل اعتماد نمونه DEC:** یک دامنه شناختی محلی مورد اعتماد با یک پرونده فعال در هر لحظه. متخصص‌های مورد اعتماد می‌توانند دانش و وضعیت نهفته موردنیاز را در محدوده منابع آزادانه مبادله کنند؛ لازم نیست برای هر Tensor سامانه سنگین مجوزدهی ایجاد شود. اعتماد به کنترلرها **به معنی تبدیل سند خارجی نامطمئن به دستور معتبر نیست**.

## کنترل مرز

سند خارجی، LoRA واردشده، ابزار و بسته مدل از مرز کنترل‌شده وارد می‌شود و خروج اطلاعات و اجرای عملیات بیرونی نیازمند اختیار متناسب است. رمز، توکن، کلید، آدرس و Hostname زیرساخت، کانفیگ VPN، لاگ خام پایش، داده آموزشی فاقد حق انتشار، معماری امنیتی مؤسسات واقعی و اسناد محرمانه همکاران نباید **در Git یا حتی تاریخچه Git** وارد شوند.

هر فایل قبل از اولین Commit بازبینی انتشار شود. حذف Secret در Commit بعدی برای محرمانگی کافی نیست. Embedding، Hidden State و Cache حاصل از داده حساس نیز نباید به تصور اینکه ناخوانا هستند منتشر شوند.

## گزارش عمومی

برای موضوع امنیتی **غیرمحرمانه** از GitHub Issue استفاده شود. جزئیات آسیب‌پذیری یا Secret در Issue عمومی درج نشود. تا زمان راه‌اندازی کانال محرمانه رسمی، می‌توان برای درخواست راه ارتباط خصوصی یک Issue بدون اطلاعات حساس مطرح کرد. آدرس امنیتی ساختگی معرفی نشده است.

جداسازی چندکاربره و چندوظیفه‌ای فقط پس از موفقیت PoC و بررسی امنیتی مستقل آینده انجام می‌شود.
